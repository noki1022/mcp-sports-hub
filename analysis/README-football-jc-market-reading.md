# 007 竞彩足球盘口阅读研究模块 v1

本研究模块只分析 007 官方竞彩报价历史快照；不预测赛果，不修改足球泊松 / Dixon–Coles 主影子模型的 λ 或 ρ，不读取皇冠赔率、多机构赔率或 NBA/CBA 数据，不发送 PushPlus，也不改现有足球抓取 cron。它的任务是将盘口从“当前一个赔率数”升级成**有时间戳、能比较、能校验**的独立研究特征。

## 算法与开源参考
- 赔率去水：现有主模型使用 multiplicative（简单归一化）。新增 `power`，求解所有 decimal odds `odds_i^(-k)` 之和为 1 的指数 k。两种概率都输出，不假设任一方法就是真实概率。参考 [`penaltyblog`](https://github.com/martineastwood/penaltyblog) 的隐含概率和去水相关公开文档；纯 Python 自行实现数学公式，不复制依赖包。
- 时间序列：每场只按真实 007 比赛 ID + 竞彩编号 + 北京时间开球 + 主客球队 ID 配对；先按独立 capture time 排序。计算每市场首末报价、隐含概率百分点变化、反向跳动次数及去水方法分歧。不能把盘口下降直接当成赢球证据。
- 让球线路：官方整数主队让球 -1 改成 -2 时，不得把“让胜”赔率/概率作为同一事件跨线比较；必须另外标记 `LINE_CHANGED_NOT_COMPARABLE`。
- 三玩法的市场约束（警告而非预测）：同一联合比分分布必须有 `P(总进球=0) ≤ P(平局)`；整数让球场的“让胜 / 让负”与普通主胜/客胜概率也存在数学上下界。跨市场独立定价与去水算法本身可产生偏差，因此仅报告不一致，不自动改方向。
- 总进球数 0/1/2/3/4/5/6/7+ 是八分类，**不是大小 2.5 盘口**。普通胜平负未开售只标记未提供，不丢弃整场。

## 输入和输出
读取来自 GitHub Actions/Release 归档且符合 `football-jc-007-v1` 的**至少两份同比赛赛前快照**。每份必须包含 `captured_at_utc`、007 比赛 ID、竞彩编号、带时区的 kickoff、主客球队 ID，以及三种玩法中已有的报价。可对多个比赛连续读取，每场按 ID 单独比较。

```bash
python3 -B -m unittest discover -s tests -p test_football_jc_market_reading.py -v
python3 -B analysis/football_jc_market_reading.py \
  --snapshots archive/football_1200.json archive/football_1800.json archive/football_2130.json \
  --out football-research/market-reading.json
```

输出保留每个来源快照的 SHA256、首末捕获 UTC 时间、每玩法赔率、去水概率、盘口线变动、异常波动阈值、跨玩法理论不一致。当前模块只运行离线测试，不修改现有定时采集与推送。它的输出应作为未来足球盘口影子模型的研究输入，而不是未校准的推荐。

## 必须在升级模型前验证的内容
1. 现有足球独立定时采集时间：北京时间 06:30、12:00、18:00、21:30；Release 中应存多时点原始数据。确认快照实际保存且赛前时间符合规则，不能把后抓取的赔率倒填入早先快照。
2. 先实现 007 真实 90 分钟终场状态语义解析与可验证原始字节，才开始盘口变化与结果的关联评估。
3. 将特征模型拆成：**M0 独立球队实力与进球概率**；**M1 市场去水概率**；**M2 M0 + 截至同一时刻可用的赔率变化、盘口更线、市场分歧**。M2 必须与 M0/M1 在相同比赛日期窗口按 Brier、Log loss、概率校准进行公平对比。不要用赌盘报价反推“独立比赛实力”，不要把博彩赔率本身误认为模型准确率。
4. 按比赛 ID 去重，训练必须早于每次验证日；同一场不同时点快照全部处于同一个 fold。观察开盘到临场变化的研究可以与收盘价格做**收盘线价值 CLV** 诊断，但只有真实同盘口、同玩法、带完整时间戳的报价才可算 CLV；初期不能报告 CLV 已实现。
5. 在足够数量的独立赛前—赛后对照样本上，检查大波动、反转、不同去水算法、市场矛盾在盲测是否带来增量信息。若没有，不允许只因盘口看似异常而更改推荐。

## 风险和不承诺
本模块不等于已学会“庄家意图”，无法根据赔率涨跌推断内幕消息，也不保证任何玩法命中率或盈利。跨平台多公司报价目前不是此模块的数据输入；将来若接入，先保证不干扰 007 主采集，并始终用可验证的采集时间比较。
