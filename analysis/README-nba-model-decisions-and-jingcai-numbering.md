# NBA 007 模型真实决策流程与竞彩编号契约

> 2026-10-30 北京时间代码审计。本文描述当前生产代码，非期望功能或已证明投注盈利。

## 1. 当前采集及预测数据

1. `scripts/titan007_join_beijing_verified.py`: 按 UTC 赛程、北京时间、主客队、007 game_id 匹配 NBA 机构让分/总分盘。
2. `analysis/nba_prediction_adapter.py` -> `analysis/nba_independent_predictions.py`: 使用比赛历史构建独立模型，模型 **odds-blind**，不把市场报价直接作为胜率特征。
3. `analysis/nba_independent_predictions.py`: 历史特征包括球队近期 form、H2H、动态 Elo；拟合主客净胜分均值和总分均值，进行残差偏差/方差校准；采集时严格排除赛日和未来比赛，最后 7 天隔离，近期 240 场作为概率校准集。输出区间、主胜概率及特定盘口下模型概率。回测性能需要另行按实际赛果验证，不能因为存在校准器就假定精度达到目标。
4. `analysis/titan007_hourly_history.py` -> `analysis/nba_hourly_dynamic_review.py`: 使用按时间保存的多个盘口快照计算升降、反转、模型和市场总分差，判断是否异常。**这部分不会重新计算球队基本胜率**。
5. `scripts/titan007_top10_companies.py` -> `analysis/nba_two_market_forecast.py`: 收集 007 十个机构 ID 的让分/总分线，计算中位数，结合模型期望分差/总分给出研究倾向。让分方向代码仍标注为 provisional；公司排名、真实报价时间需逐一验证；研究倾向不是胜率、投注优势或正式下注建议。
6. `analysis/market_decision_gate.py`: 只接受模型时间截断、历史校准、精确盘口线及方向全部匹配的概率。
7. `analysis/market_value_policy.py`: 价值候选规则默认 **disabled**，需证明历史赔率与赛果验证有效后才可启用。默认不产生投注建议。
8. `analysis/nba_injury_context.py`: 提供伤停背景质量，现阶段球员伤停尚未作为经过回测的数值调整进入独立预测概率。
9. `scripts/titan007_jingcai_three_market.py`: 独立读取 007 公开奖金文件，保留初赔/即赔、市场缺失与来源信息；不能混同商业机构盘口。

## 2. 盘口分析的严格区分

- **模型净胜分**：模型对 `主队得分 − 客队得分` 的期望值。
- **模型总分**：模型对双方得分总和的期望值。
- **让分判断**：对比正确符号和方向的竞彩主队让分值，必须使用 007 明确的正负号说明（`+` 客队让主队；`−` 主队让客队），不能把多机构盘差直接套用相同符号。
- **大小分判断**：先比较模型总分和相同时间、相同市场的现盘总分线，盘口差只是研究信号；真正的概率应取模型分布下越过具体盘口线的概率，并检验样本外校准。
- **去水市场概率**：在一个明确二选一市场、同一盘口和同一时刻，`q1=(1/o1)/[(1/o1)+(1/o2)]`。这只是市场隐含概率，不是模型独立概率。
- **正期望判定**：必须有方向与结算规则验证、同盘口实时报价、合理校准的模型概率，以及可复盘的历史测试；不能只用 `模型总分 - 机构盘口` 的绝对值宣称投注优势。
- **每小时变化**：保存价格、盘口、采样时间；比较每次采样与前次的变化。首次采样只能作为基线。需区分外部伤停消息和盘口变动本身，避免双重计数。当前版本只输出观察性研判。

## 3. 用户手机推送：只能用竞彩编号

- 实际用户侧编号从 `jc.titan007.com/xml/bf_jc_lq.txt` 的赛程记录读取，例如 `周五309`；不使用内部 007 `728165` 当场次编号，也不按展示排序生成 `#01`。
- `scripts/verify_007_jc_push_numbering.py` 检查 **相同 007 game_id、主客队顺序、北京时间开赛时间和三位彩票编号**。未验证则只允许展示 `竞彩编号待核`，禁止递增造号。
- `scripts/titan007_jingcai_three_market.py` 随既有采集流程取得并保存映射；`scripts/pushplus_mobile.py` 同其他赔率/模型数据合并；`scripts/pushplus_mobile_v2.py` 在速览和详细分析中显示彩票编号并按号码顺序展示。
- 2026-10-31 十场历史固定董事会实测：`周五309`–`周五318` 全部通过；未将该规则硬编码为每天均从 309 开始。
- 保留 NBA 内部 ID 仅用于关联、历史快照、脚本日志；模型仍按真实 ID 匹配，不影响排序后的赔率和概率身份。
- 007 本身声明页面提供的奖金以实际出票为准；竞彩玩法不销售、未报价与采集失败应保留不同状态。

## 4. 当前最重要的未完成工作

1. 用当前有效竞彩盘口线和已验证市场方向计算 **单个玩法** 正态/残差校准概率；赔率概率去水与模型概率独立保存。
2. 把三次／每小时记录的竞彩奖金变化纳入观察报告，必须具备同市场同方向同赛季的历史序列；不自动把单次波动解释为庄家意图。
3. 采用严格时间顺序的历史训练、验证和盲测，按 NBA 比赛结算回测 竞彩让分与大小分，指标含 Brier、log loss、覆盖率、ROI 与样本量/置信区间。
4. 伤停和预计阵容只有在真实来源和独立回测证明确实改善误差时才作为模型数值特征。
5. 复核竞彩玩法开售状态及出票时奖金差异；未通过证据门槛时保留研究倾向，不为了填满赛事强行推荐。

## 5. 如何验收一次手机推送

必须同时满足：彩票编号真实并与球队匹配、北京时间正确、模型预测与数据质量展示、机构让分和总分变化展示、竞彩各玩法实际奖金和开售状态展示、数据源/采样时间可追溯、没有凭空胜率或强制推荐。缺失数据应显式说明，不可用外部机构市场赔率填补。
