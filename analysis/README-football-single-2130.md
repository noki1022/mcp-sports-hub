# 足球单模型定稿与复盘约定（北京时间）

本仓库足球与 NBA/CBA **模型、定时任务、盘口结算和评分数据独立**。足球只保留一份由 007 近期赛况、交锋、已核实伤停、竞彩胜平负/让球胜平负/总进球及多机构真实亚洲盘共同形成的融合预测。原始泊松中间结果仅用作计算，**不是第二个独立评分模型**；旧 Dixon–Coles 足球影子 job 不再调度。

## 唯一评分答卷

- GitHub UTC `30 13 * * *` 为**北京时间21:30**，执行单份足球融合模型；归档到当日 `football-jc-final-YYYYMMDD` Release，文件 `football_jc_final_2130.json`。按 create-only 保存，不覆盖同名已存在的冻结答卷。GitHub Actions 触发可能延迟，归档同时记录实际采集/生成时刻；显著延迟的报告不得冒充21:30的准点版本。
- **北京时间06:30**（UTC 22:30，前一 UTC 日）继续基于最新 007 数据生成报告，但读取前一晚 **21:30冻结文件**，逐场、逐玩法比较。只对改判/竞彩官方让球换线写简短：`21:30判断 → 06:30判断 → 有证据的原因`。可依据已核实的机构让球众数/中位线变化、已核实伤停、模型预期进球差等。没有可核实原因时明确写“具体驱动因素尚未确认”，不得猜庄家意图。
- **06:30不能修改21:30文件，不参与正式评分**。其他时段仍为独立采集和观察数据。
- 竞彩让球是**主队带符号整数**：如主 -1，主队 2:1 对客队为 **让平**，不能写亚洲盘“走盘”。亚盘主 -0.75 赢一球可能赢半，仅用于市场信息，不等于竞彩三项让球玩法。
- 报告默认北京时间、主队在左、客队在右、竞彩编号不省略；iPhone 简洁版参考既有 NBA 五玩法 HTML 排版，只输出足球三玩法；总进球可推荐两档，必须写各档概率和合计覆盖概率。

## 每日复盘

复盘程序 `analysis/football_jc_single_final_review.py` **只允许**21:30冻结预测与带 007 原始证据的 90 分钟正式赛果匹配，按竞彩胜平负/整数让球胜平负/总进球数三玩法统计命中率，未中必须附真实主:客比分、真实赛果；未开售、未验证或未完赛不能计入准确率；06:30改判不计分。格式与 NBA 复盘相同：三玩法概要 + 逐场结算 + 异常/缺数据说明。

**仍未完成的外部依赖**：007 公开 `bf_jc.txt` 当前实盘采集只取得待赛比赛，尚未单独验收完整 90 分钟终场状态和比分解析。因此复盘程序虽有离线验收/模拟赛果测试，**尚不能声称已经上线每天自动真实赛果复盘或得到实际命中率**。只有接通经原始字节和状态字段核验的 007 FT 数据后，才可开启定时真实评分和复盘推送。不要用赛前即时比分或加时赛果代替终场数据。

## 推送

21:30和06:30在计划运行成功且通过冻结文件 SHA256 核验后，经独立足球 PushPlus 发送。专用密钥优先 `FOOTBALL_PUSHPLUS_TOKEN`，当前支持部署环境的 `PUSHPLUS_TOKEN` 作为兜底。PushPlus API 接受不等于 iPhone 已实际收到。若缺失21:30冻结文件，06:30比较必须失败并告警，绝不伪称“无改判”或无声地跳过冻结对照。
