# 007 竞彩 NBA 编号丢失｜雷霆名称匹配根因取证（2026-11-02，北京时间）

## 结论

真实源地址 `https://jc.titan007.com/xml/bf_jc_lq.txt` 在北京时间 2026-11-02 晚间、Nov3赛前返回了ID `728298`，竞彩号 **周一302**，007 竞彩主队别名 `['骑士','騎士','骑士']`，客队别名 `['雷霆','雷霆','雷霆']`。007 实际编号并未缺失，也不是反向主客；代码中球队全名 `俄克拉荷马城雷霆` 相较于 `雷霆` 多 **6个汉字**，而旧 `comparable()` 只允许简写后缀差 **≤5个汉字**，因此只有这场雷霆客队在源身份校验时失败，造成 `HOME_AWAY_MISMATCH`。

这不是暂时抓不到编号，也不需要随意猜测302。原始 007 赛程源已经给出了正确的编号、比赛ID和主客方向。

## 修复和安全边界

仅建立已经通过实际源证实的 `俄克拉荷马城雷霆 ↔ 雷霆` 允许别名，并继续要求 **同一007比赛ID、各自正确的主客字段、赛前北京时间、合法三位数期号、整场不重复**。不放宽通用后缀的字符长度上限，更不自动交换主客或修改机构报价/赔率方向。对于发生真实失败的其他球队，保存 `identity_diagnostic` 包括球队全称、007源别名、双侧相互匹配结果、是否可能反向，以便日后直接复现分析。

原先的 `config/nba_jc_user_confirmed_numbers.json` 人工302条目继续仅作为回退显示的有来源编号；有真实007正确编号时，优先 `VERIFIED_JC_NUMBER`。两者不冲突。不会以人工编号修复重新标记机构报价方向可靠性。

## 根因防再发规则

一旦出现 `HOME_AWAY_MISMATCH`，必须保留原始000/007 ID及双方别名和各侧比对状态；不允许被泛化为“竞彩场次未开”，也不允许从列表序号生成彩票编号。新增别名必须由真实公开赛程或足够可信的球队实体对应证据验证，经反向主客、同名球队碰撞、时间戳和完整赛程回归通过，才能进入代码。原数据与错误原因始终可追溯。
