# 足球动态模型：赛前上下文特征账本（研究阶段）

## 目的
模型优势应该来自可核对、可比较、可回测的细节，不来自“猜比分”或盲目跟随最低赔率。
本阶段先将真实 007 证据整理为时间点固定的特征；**只做记录，不训练或修改任何生产权重**。
现有篮球/足球 12:00–23:00 整点推送、足球 21:00 评分、Cloudflare 去重及历史快照均保持原样。

## 已落地的数据层
- 007 比赛 ID、竞彩销售编号、联赛 ID、主客 007 球队 ID。
- 近五场进失球、主客场记录、3/1/0 积分、最近三场相对前两场攻防差、上场比赛到本场的开球时间间隔、近 14 天赛程数量。
- 每场最近比赛的对手球队 ID；用于未来做按联赛/对手难度校正，当前绝不冒充“已校正实力”。
- 有效历史交锋数量、伤停原始名单数量及其可用性状态。
- 每小时原始抓取快照的 SHA-256，确保未来回测严格按当时数据重建。

## 当前还没有可靠赋值的因素
| 特征 | 当前状态 | 要达到可训练状态还缺什么 |
| --- | --- | --- |
| 赛季球队攻防实力 / Elo / xG | 未建模，不用零填充 | 完整赛季已核实完场数据、固定联赛和赛季身份、赛前已存在的球队历史 |
| 对手强度校正 | 对手 ID 已保存；强度未知 | 各对手在本场赛前的历史评级、同赛事主客场对照 |
| 主客场真实优势 | 五场内的客/主样本已标记，样本小 | 同联赛多年样本、时间衰减及分层正则化 |
| 最近休息 / 密集赛程 | 保存**开球间隔代理量**，非实际恢复时间 | 完整赛程、杯赛/补赛、旅行距离（如可靠） |
| 核心伤停和预计出场时间 | 007 名单不代表确认缺阵，当前不能自动赋权 | 带观测时间的球队名单/赛前首发、实际出场分钟及关键球员能力 |
| 转会、轮换 | 未取得可靠时点数据，保持未知 | 官方注册/转会时间、出场记录和有证据的阵容轮换 |
| 亚洲盘口、欧赔转换 | 独立市场诊断，不作为特征事实 | 同场同点位主客方向一致、盘口/水位时序和独立赛果检验 |

## 学习路径（绝不使用结果倒灌）
1. 保存全部当前时间点原始记录与特征，不覆盖任何历史数据。
2. 建立已独立核实的完场历史库：赛事 ID、球队/联赛/赛季、90 分钟比分、完赛确认时间；合并不同采集中的同一场，不把 007 nearMatches 的比分自动当作官方赛果。
3. 按时间滚动训练球队攻防与主场优势，补充对手实力校正；低样本联赛采用收缩，缺失因子不填零冒充。
4. 逐项新增伤停、转会、阵容、赛程影响；每次新增进行消融实验（是否真的改善概率损失/校准而不是仅提高历史命中率）。
5. 严格仅使用该场赛前可见数据；21:00 不可变评分基准与市场报价保持独立，最终比较胜平负、让球胜平负、总进球数的 Log loss、Brier、校准、覆盖率和完整性。
6. 只有验证集、独立测试集及后续实盘盲测证明改善，才允许提出调权 PR；**不会自动修改正式推送**。

## 输出和失败处理
- 生产抓取完成后，新增只读 `football-output/football_context_features.json`。
- 输出和原始 007 快照、现有候选文件进入同一历史归档。每一场都有“可用/隔离”标记。
- 特征提取故障不阻断主模型；错误明确记录，绝不拿报价填补缺失统计。
- `analysis/football_context_features.py` 独立可重放；`tests/test_football_context_features.py` 验证赔率更改不影响提取、比赛开球后数据不能进入、本赛季强弱和未核实人员影响仍为空。
