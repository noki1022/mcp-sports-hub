# 足球模型：直接融合 007 真实亚洲机构盘口（研究版 v1）

## 目的与真实数据边界
当前足球独立工作流已经打通 007 竞彩胜平负、让球胜平负和 0~7+ 总进球数，近五场、交锋、伤停原始清单，以及每场多家机构亚洲让球主线（每家初盘水位、当前水位、盘口修改时间、港水）。这些数据足以用于**当期、未校准的规则融合**，无需先下载长达多年的盘赔历史。

注意：现有多时点原始快照已按足球目录归档，但缺少足够多具备赛前冻结时间和独立终场核对的历史样本，因此任何融合权重均尚未训练验证，不能宣称提升真实命中率、正收益、CLV 或胜率保证。

## 输入与算法
先用现有独立泊松模型计算主客预期进球（融合近五场、有效交锋及已明确缺阵且有时间戳的伤停，未经核实的伤停不改动概率）。之后用每家真正不同机构的 **主线路**计算盘口更新：

1. 校验 007 比赛 ID、接口来源 URL、场次开球时间、真实采集时间、主客让球统一正负号、价格修改时间、有效港水、同一家机构 ID 去重；仅使用 `main_line=true`，不把备选盘口充当额外机构。
2. 亚洲主让 -0.75 与竞彩官方整数 -1 不是同一种结算。对每家公司当前的亚洲实际让球，用比分矩阵计算主队赢份额 W、输份额 L；亚洲盘走盘和赢半/输半按照结算比例处理。当前港水用 Decimal=港水+1，再去水归一化成隐含的 W/(W+L)；当固定进球总和时，单调反解进球差相对独立泊松期望的偏移。
3. 当比分总和过低而无法精确反推大幅让球时，保留**强烈盘口方向性分歧**而不是编造精确进球差。此时将报价标记为 `SATURATED_DIRECTIONAL_ONLY_AT_FIXED_TOTAL`，仍可作为有严格最大幅度的方向修正信号；所有公司方向明显矛盾则拒绝改动。
4. 最少 5 家不同机构有效报价。按各机构隐含进球差偏移的中位数，去除偏移超过 0.5 球的异常报价；报价一致性不足时拒绝融合；仅取 25% 的未训练启发式权重，实际预期进球差最多改动 0.30 球。
5. 保持两个球队的**预期总进球和不变**，只改变分配差。重算一个一致的比分矩阵，统一生成三玩法概率以及最多两档总进球数推荐。亚洲盘口本身无法给出总进球信息；总进球数仍由近五场和历史交锋主导。

## 工程部署和文件
- `football-output/football_jc_forecast.json`：**未经机构亚盘修改的原泊松答案**，用于原样保留、对照及独立 Dixon–Coles 影子模型评价。
- `football-output/football_jc_forecast_market.json`：实际亚盘融合后的足球竞彩三玩法答案，每场附 007 原始数据指纹、参与机构、被拒机构、盘口方向性信息、调整前后预期进球、应用原因。
- `football-output/football_jc_mobile.html`：从**已融合后的足球预测**生成 iPhone 版报表；篮球 PushPlus 完全不变。
- `football-output/football_jc_euro_asian.json` 与 `football-output/football_007_asian_real_compare.json` 仍单独保存理论/真实欧亚对照。
- 已有 Github Actions 按北京时间 06:30、12:00、18:00、21:30 分别运行足球链路，本 PR 不改变触发时点或 Cloudflare。

没有盘口、少于五家有效机构、盘口方向分歧过大、盘口时间超前、异常水位、源 ID 不匹配时，退回原独立模型概率；绝不以假盘口覆盖真实竞彩赔率。一场普通胜平负不开盘时仍根据模型给出方向和概率，标注未提供官方报价，让球胜平负及总进球数照常输出。

## 回归和效果边界
PR 内 `python3 -B -m unittest discover -s tests -p test_football_jc_asian_assimilation.py -v` 检查亚盘正负号、输赢半结算、时间防泄漏、重复公司、异常价格、市场过深的冲突标记、少机构回退、三种竞彩玩法概率总和、缺少官方 HAD 不丢整场及独立原模型完全不变。

本阶段**完成的是功能集成与实际输入覆盖验证，而非准确率升级证明**。未来真实终场赛果确认后，应比较同场同时间 `独立泊松 M0`、`007机构亚盘融合 M1`、`Dixon–Coles影子 M2` 在胜平负、让球胜平负、总进球数上的概率校准、Log loss、Brier 与命中率。先独立盲测再调参，不能用比赛后的走势反推赛前权重。
