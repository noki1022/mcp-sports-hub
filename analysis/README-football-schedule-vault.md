# 足球独立定时采集与原始数据归档

此工作流与 NBA/CBA 的定时、模型、PushPlus、Cloudflare Worker **完全不共享运行逻辑**。足球只调用 jc.titan007.com 已核验的两个公开足球竞彩源，保留源文本、SHA256、抓取起止时刻、原始赛事与已验证赔率。模型依然独立运行；若球队近五场、交锋或伤停尚未核验则明确不出预测，不发送推送。

## 北京时间定时（GitHub Actions cron，UTC）
- 06:30（UTC 22:30 前一日）
- 12:00（UTC 04:00）
- 18:00（UTC 10:00）
- 21:30（UTC 13:30）

GitHub schedule **可能延迟或漏触发**；这些只是配置时点，不能承诺严格准点。该阶段只有数据抓取、离线分析和归档，**没有足球 PushPlus 自动推送**。下一阶段将单独设计 3–30 分钟临场动态窗口、幂等推送和 Cloudflare 备用触发，绝不接入篮球现有 Worker。

## 原始数据保全
- GitHub Actions 每次运行把足球原始公开 feed 存成 gzip，并生成 raw/manifest.json，含 URL、SHA256、大小、实际抓取起止时间。
- 无论解析成功与否，原始响应会优先保存；解析失败不能污染模型或生成假赛程。
- 上传 GitHub Actions artifact 90 天作为短期排障证据。
- 每次自动/手动运行另有独立 archive-football-raw-release job，将 zip 按北京时间日期写入 GitHub Releases，资产名包含 GitHub run_id 防覆盖；不把逐日大文件直接提交到 Git 仓库。
- GitHub Releases 仍是**单一平台存储**，不是异地备份，不能保证绝对不丢；后续需增加 R2 或其他独立备份和恢复演练。
- 归档只在实际 Release 上传成功后视为成功；失败的 run 必须报警、重试和补档。当前没有自动报警或双调度，不得宣称已实现高可用。
