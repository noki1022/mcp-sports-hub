# 篮球、足球长期采集、训练、回测与数据安全执行方案

版本：v1，2026-11-06（北京时间）。本方案以当前仓库可核验代码为准。
目标是长期保全实盘证据、建立可复现训练与评价闭环；不承诺固定命中率。

## 一、先明确样本口径

一场比赛的19次快照×10家机构，并不是190场独立比赛。全部原始快照永久保留，
用于计算轨迹、反转、稳定持续时间、采样缺口与机构分歧；统计独立样本数时按比赛计数。
同一比赛的所有时点、所有机构、所有玩法不得跨训练/验证/测试的日期边界。
首轮无历史正常分析；无变化是有效观测，抓取失败、封盘和未开玩法分别记录，不能填充为0。

正式评分继续使用已冻结的逐场赛前最终版；21:30保留历史基准，不事后挑命中的时点。
研究可以分别评估提前24小时、6小时、1小时、最后赛前四个窗口，但禁止将四个窗口混算四场。
本次自动权重研究采用一个最终版/比赛/玩法，其他窗口与轨迹特征的训练是下一阶段扩展。

## 二、数据分层和目录责任

| 层级 | 内容 | 持久化位置 | 可否重建/覆盖 |
|---|---|---|---|
| 代码及小配置 | 模型、解析器、政策、测试 | main | 走PR，保留Git历史 |
| 篮球原始层 | 每次抓取原文、gzip、SHA256 manifest | 现有 archive/nba-market-captures 分支 | 不自动删除或覆盖 |
| 足球原始层 | 每run原文ZIP、manifest、多机构及伤停源 | 现有 football-007-raw-日期 Releases | 不自动删除或覆盖 |
| 赛前候选/最终版 | 原始候选哈希、生成时间、比赛身份、概率 | 现有候选资产、sport-pregame-final-* Releases | 只追加，同名异内容拒绝 |
| 赛果与评分 | 独立已验证赛果及冻结答卷关联 | 现有独立复盘流程及其Releases | 更正须新版本，禁止改旧答卷 |
| 派生数据与研究 | 来源目录、合格JSONL、隔离原因、评估与manifest | 新 sports-data-lifecycle-月份 Releases | 可重建；每run/attempt追加 |
| 临时排障 | Actions artifacts | 14天（新流程） | 允许到期，不能当长期原始备份 |

main不新增每日大数据集；新训练产物不提交Git。已有原始分支仍会增大，分支隔离
不能消除整个仓库增长。现阶段继续沿用既有归档，禁止为“整洁”直接删除历史或重写Git。
400 MiB预警、800 MiB严重告警是本项目内部管理阈值，不是GitHub官方配额。
超过预警后先验证可恢复副本，再单独实施新数据转对象存储/Release分片方案；
历史迁移必须有前后文件数、字节数、哈希逐项对照和回滚点。

## 三、准入与防泄漏

新 `ops/sports_learning_dataset.py` 严格连接候选→最终版→独立复盘：

1. 校验候选bundle/record、final、review的SHA256；最终版必须与原候选身份、时间和全部盘口一致。
2. 必须有GitHub资产创建时间证明候选已在开赛前发布。只写一个“赛前时间”的JSON不够。
   历史迟到归档可保留作研究，但不能冒充有赛前外部见证的正式评估样本。
3. 赛果必须匹配同场、主客、原候选哈希，且来自标记已执行独立赛果验证的现有评分流程。
   新准入器依赖该流程的原文验证，不把review自身哈希当成赛果真实性的独立证明。
4. 特征可用时间≤预测时间<开赛时间<标签可用时间。标签可用时间采用已验证review资产发布时间，
   这是保守的“最迟已知可用时间”，不能用于倒推更早时点已有赛果。
5. NBA市场基准必须是同方向、同盘口、去水后的概率；缺独赢多机构报价时不拿让分概率硬代替。
   足球用真实竞彩对应玩法的去水概率，绝不把两项亚盘当成三项让球胜平负。
6. 足球按联赛区分；新增候选携带league。老候选仅能从原归档中完整快照的SHA256与候选source_snapshot_sha256一致、
   比赛ID/主客ID/名称/开赛时间全部吻合时恢复联赛元数据，不能改写旧候选；无此证据继续隔离。NBA与CBA不得混训。
7. 冲突最终版、冲突标签、同时间不同概率、走盘/未完赛/未开玩法全部按原因隔离。
   隔离是“不入训练”，不是删除原始数据。修复后可按新版本重建，保留旧版本与原因。

当前适配器只接收已发布的逐场冻结与复盘资产；旧整批比分文件缺乏这些证据时不会强行导入。
仍保留原有历史研究工具处理那2万多场历史数据，不能给它们补造盘口时间或赛前发布证据。

## 四、模型怎样逐步训练

基础强弱、近期状态、主客、休息/赛程、伤停及交锋仍由现有独立模型提供。
新增动态特征分四组：盘口/去水概率水平，累计/最近变动和每小时速度，机构一致性/分歧，
以及无变化持续时间、报价年龄、封盘恢复、缺采样等质量特征。伤停只有已验证且时间合格的信息可用；
市场走势不能反推“某球员必定缺阵”。历史轨迹必须用同一基线/尺度重新解释，避免基线变化混入盘口变化。

**本次已实现的第一阶段权重训练**：`analysis/sports_weight_learning.py` 对二分类、多分类共用
概率向量接口，训练现有生产概率与同玩法市场基准的额外收缩融合权重。生产概率可能已经融合
市场信息，因此本次权重是增量校准参数，不代表模型的总市场占比，也不冒称独立无市场基线。预先固定候选权重
0、0.05、0.10、0.15、0.20、0.25、0.30，不能看测试集后追加参数。
这不是竞彩/皇冠7:3；7:3是业务优先级，不能混成概率权重。

**后续动态系数阶段**：在足够跨日期样本后，逐组加入轨迹、伤停交互和机构分歧，采用带正则的
残差/多分类模型；每次只增加一个特征组并做消融。先验证盘口不变组、变盘组、反转组、缺伤停组
各自的效果，再决定是否启用。当前PR没有宣称已完成这些动态系数的训练，也不会自动改正式权重。

## 五、时间回测与上线条件

政策保存在 `config/sports_learning_policy.json`：训练跨度至少60天、至少20个不同比赛日、100场训练比赛；
随后14天验证、14天测试，两侧各隔离2天，验证/测试各至少30场。按运动×联赛×玩法×模型版本分别执行。
跨度和实际比赛日分别检查，避免足球每周赛程被误要求每天都有比赛；全组共用北京时间切分边界。
这些是保守的研究准入下限，不是对用户推送或“重点关注场次”的限制，也不是精度保证。

训练集只负责选择权重；验证集若不优于原模型则回到权重0；测试集仅评分，不选参数。
每日滚动重算不算新的独立前瞻验证，严禁根据不断查看的测试成绩反复挑模型。
输出Brier、Log Loss、准确率，总进球另列两个进球桶的覆盖率；按日期成组bootstrap给出Log Loss差异95%区间。
所有数据和政策都有哈希；输出明确记录切分边界、样本数、拒绝原因和候选权重。
不足时输出INSUFFICIENT_INDEPENDENT_HISTORY，不伪造训练成功或“预测提升”。

正式替换前必须完成：多个时间窗口的稳定回测、比分/盘口/伤停独立数据核验、
冻结候选后新的前瞻比赛验证、校准曲线与分组表现检查，以及与现有版本同场同线比较。
回测通过只允许进入前瞻验收，不自动晋升。只保留一个正式推送模型和一套正式评分；
离线研究版本不增加用户推送或第二份正式成绩。

上线版本必须绑定代码SHA、数据集manifest、政策SHA、训练截止、指标、适用联赛/玩法、
上一正式版本及回滚说明。新参数通过独立PR激活。出现输入模式变化、哈希异常、概率异常或
前瞻指标恶化，冻结更新、继续使用已验证版本；不能一边修改参数一边改历史评分。

## 六、自动执行与异常恢复

新 `sports-data-lifecycle.yml` 在足球采集、篮球日间/21:30/06:30/夜间采集、逐场冻结或NBA独立评分完成后触发，
北京时间12:40另有补偿检查；执行在生产推送之外，不阻塞推送。GitHub队列仍可能延迟，
这是事件驱动的及时审计，不承诺秒级实时。

前置 `ops/sports_candidate_archive.py` 将Git中现成的篮球日间与06:30候选原字节追加到
既有nba-silent-actual-日期Release。包括次日赛程目录，避免中午抓到明日比赛时漏档。
同名同内容幂等、同名异内容立即报错；不重算概率，不把迟到补档冒充赛前发布。
读取/恢复旧数据不等于承认其已有赛前外部见证，新准入仍检查资产真实创建时间。

每轮读取最近120天资产元数据，校验合格JSON证据与足球ZIP根raw/manifest声明的原文，
输出目录、准入结果、训练研究、manifest，并上传月度Release。超过500MB单轮读取预算或
遇到损坏会明确失败/报告未检查项，不能显示“全部安全”。缓存仅在实时GitHub资产digest、大小与身份
匹配时复用；JSON缓存每次重验字节哈希，ZIP已验收据每月失效，要求重新下载校验。
PR测试作业仅只读权限、不写缓存；写缓存/Release的作业仅接受本仓库main的非PR运行，
不执行上游上传的代码或脚本。GitHub的workflow_run默认缓存只读，因此在上述严格隔离的
main作业显式声明cache-mode: write，保证事件触发时的增量进度能保存。
每次完成一项即原子写缓存；预算不足时保留已验进度，下一事件继续，未完成前一直标记INCOMPLETE。
缓存丢失就重新下载，不能把缓存当原始备份。当前是120天滚动研究窗口内的增量校验，尚未有
跨年全量训练索引；窗口之外原始数据仍留在既有归档，不自动删除。历史年度研究需另设冻结分片。
篮球原文逐字节校验继续由现有 `nba-raw-vault-backup.yml` 执行；本流程不重复冒称已检查全部NBA原文。

新流程故障不自动发额外PushPlus消息，以Actions失败、摘要及保存的health报告呈现；
告警推送可接现有经授权健康监控，避免新建重复发送入口。新流程不自动补造缺失原始响应。
遗漏run先检查原artifact是否仍存在，找到后按原run/attempt补档并再次验SHA；找不到则永久记录缺口。

## 七、备份、安全与恢复演练

GitHub分支和Releases仍是同一平台，不能算独立灾备。按此前决定，R2仍延期，
本次不创建收费资源、不猜测密钥、不声称独立备份已启用，也无法承诺绝对不丢数据。
现有R2镜像代码待配置后，应进行上传→读回→解压→SHA比较→重建索引/样本的完整恢复演练。

每月应随机抽取篮球/足球各一个完整比赛日，核对计划批次、实际run、归档清单、各文件hash、
候选、冻结最终版与复盘；每季度做跨月份恢复。演练失败不得删除/迁移唯一副本。
本次已有原文完整性检查，但尚未实现定时完整恢复演练；这作为独立验收项，不能用校验脚本替代。
密钥仅放GitHub Secrets，日志不打印；采集和模型生产按最小权限，审计程序只读源数据；
发布派生产物仅有创建Release资产权限需求，代码不含远端删除或覆盖命令。

报告分别列出原文完整性与learning_readiness；缺验证复盘时明确BLOCKED_NO_VERIFIED_REVIEW_ASSETS，
并记录逐场隔离原因。原文哈希正确、采集流程绿灯不等于训练闭环已经有标签。
赛果接入使用 `sports-verified-results.yml`：冻结答卷工作流完成后触发，
另有每小时第50分钟的恢复检查，回查最近7个北京时间比赛日。
从007单场原文或ESPN原始响应提取明确完场比分，校验比赛ID、主客队与开赛时间，
再对原冻结答卷逐场评分；整日赛程完整性门禁仍单独保留。
每份Release复盘JSON自带gzip压缩原文、SHA256、来源、观察时间和冻结答卷哈希。
训练准入时重新解析原文并重算评分，拒绝“哈希正确但比分自填”的结果。
不得用“完场可能性”、搜索摘要比分或未核验状态码构造训练标签。

初版足球自动准入限原文明确的联赛轮次及杯赛联赛/小组阶段；淘汰赛、加时、点球、
常规时间不明的赛果留待核验。NBA按ESPN美国比赛日期及相邻UTC日期查找，
不以北京时间日期直接替代源站日期。未完赛不记为未中。
已发布复盘只读重放，不覆盖；上游后续改判须单独追加经审计的更正记录，
当前版本不自动覆写历史标签。超过7日的延期赛事需显式历史补查。
该流程仅归档和训练准入，不增加推送、不重算过去预测、不自动晋升权重。

## 八、验收清单与当前落地边界

- 已编码：政策、二/多分类权重研究、按日期及模型版本隔离、事件去重、样本准入、候选league补充、
  赛前外部发布时间验证、比分/方向交叉检查、足球原文manifest校验、按digest增量缓存、容量告警、派生产物哈希及独立自动工作流。
- 合并后生产验收：首轮事件触发、Release持久化、真实合格样本数与所有隔离原因。
- 数据不足即不训练；没有独立前瞻证据即不晋升。此时原生产模型和推送继续工作。
- 未完成且不得冒称：自动全量回补、跨年增量索引、动态特征系数训练、滚动多折晋升、
  独立R2副本、定时完整恢复演练，以及实盘命中率提升。
